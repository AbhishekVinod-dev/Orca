1. Project Overview
ORCA is a conversational marine intelligence platform designed for marine stakeholders such as fishermen, coastal authorities, disaster management agencies, and researchers. The frontend provides a unified interface through which users can ask natural-language questions and receive evidence-oriented marine intelligence about Potential Fishing Zones (PFZ), sea safety, tides, weather, sea state, cyclone and lightning alerts, chlorophyll and SST hotspots, vessel routes, geofencing alerts, and explainable reasoning.
This version is intentionally frontend-only. All responses, map layers, alerts, evidence, agent traces, and visualizations use mock/dummy data. The code structure should allow these mock services to be replaced with real backend APIs later without redesigning the user experience.
2. Product Goals
Provide a conversational entry point for marine intelligence.
Combine chat, geospatial visualization, evidence, and alerts in one interface.
Demonstrate an agentic workflow visually through planning, data retrieval, correlation, and response stages.
Support multi-turn conversations and follow-up/refinement queries.
Make recommendations explainable by showing correlated data sources and reasoning traces.
Support desktop control-room workflows and mobile use at sea or in harbors.
Keep the frontend API-ready so real marine, weather, satellite, oceanographic, and geospatial services can be integrated later.

4. Core User Experience
The product is designed as a purpose-built maritime command console rather than a generic dashboard. The primary interaction is conversational, while the map and evidence panels provide visual and factual context.
Primary flow
User opens the ORCA landing page.
User selects “Ask ORCA”.
The application opens the main app shell.
User chooses a quick action or enters a natural-language query.
The chat displays a simulated agentic pipeline: Planning → Retrieving data → Correlating → Generating answer.
ORCA returns a response with supporting evidence and, where relevant, inline map/chart cards.
The contextual map updates with PFZ markers, alerts, routes, heatmap layers, or geofences.
The user can ask a follow-up question while retaining conversation context.

Integration convention: keep all external calls inside services/*.ts. Components should consume typed service functions rather than calling fetch directly. This makes backend integration a replacement of service implementations rather than a rewrite of the UI.
10. Agentic UX Simulation
For the frontend-only prototype, simulate an agent pipeline with timed states:
Planning — understand and decompose the query.
Retrieving data — load mock marine/weather/GIS evidence.
Correlating — simulate cross-source reasoning.
Generating answer — render the final conversational response.
The UI should show these states in the chat/evidence area and then persist a compact trace after the response is generated.
11. Visual & Interaction Design
Primary aesthetic: deep ocean blues and teals.
Dark control-room theme enabled by default.
Optional light theme.
Clean sans-serif typography.
Subtle glassmorphism for floating panels over map imagery.
Alert colors: green for safe, yellow/orange for caution, red for severe/critical.
Avoid generic admin-dashboard styling; prioritize map, conversation, evidence, and marine context.
Use responsive panel collapse on mobile so the chat remains the primary interaction.

19. Project Summary
ORCA's frontend should feel like a marine command console with conversation at its center. The strongest experience is not a collection of disconnected dashboard pages; it is a workflow where a user's question causes the chat, agent trace, evidence, alerts, and map to update together. The frontend prototype therefore serves as the interaction and visualization layer for a future agentic marine-intelligence backend.
